# 探针契约：防止形状假阳性

这份参考把真实 Agent 验收中出现的假阳性抽象成通用探针模式。它只描述判据，不绑定某个项目、模型、框架或端口。写探针前先读本文件；不需要写探针时不要加载它。

## 七类常见弱断言

| 弱断言（错误） | 最小失效输入 | 需要的独立契约 |
| --- | --- | --- |
| HTTP 200 且有 `vision_status` 就算视觉成功 | `vision_status=error`、模型字段为空 | 明确 `applied`、实际模型标识非空、图像计数正确；另测安全降级 |
| 两次 200 且 `message_id` 相等就算幂等 | 两次响应都缺 ID 或 ID 为空 | 非空 ID、请求主体/租户/会话/幂等键完全一致、持久化响应可读、状态读回一致，并核对执行次数和真实副作用 |
| `intent_method=model` 就算模型理解正确 | 所有输入都返回同一意图，答案不随变量变化 | 由外部真值定义的成对/未见输入；输入改变时意图、答案或动作边界按契约改变；不能从实际答案生成 expected |
| 导入返回 `count > 0` 就算成功 | 条目 ID、文件名、租户、版本或正文不对 | 每个返回条目非空且唯一，原件与数据库/索引行可对账，租户/来源/版本/状态正确；解析失败不能用伪数据填充 |
| Demo/Host health 都 200 就算页面可用 | UI/管理页是空壳、关键标记缺失或状态未刷新 | 对交付声明的每个真实入口走最小用户旅程，核对页面、API 和后态；health 只证明健康接口 |
| 解析器异常但写出最小字节文件就算 PDF 通过 | 生成/解析异常后仍有“非空 PDF” | 输入文件必须被独立解析器验证，中文/关键字段/页序/表格可核对；夹具失败记录为测试缺陷，不默默降级 |
| 回滚 HTTP 200 且候选字符串改变就算回滚成功 | 候选、知识、索引、API 和页面后态互相矛盾 | 先声明状态机和映射，再对账关联 ID、可检索性、退休/生效状态、审计和页面/API；不要求所有层使用同一字面值 |

这些弱断言即使让 CI 变绿，也不能关闭能力行。每个探针至少保存原始输入/响应和解析后判断；解析器遇到错误类型、缺字段或空 ID 时应返回明确的非通过结果，而不是把缺失值的相等性当成成功。

探针的异常处理也属于证据契约：只捕获预期的、可命名的解析或业务异常；未预期异常必须保留原始堆栈并以非零退出或明确 `INCOMPLETE` 结束。用 `except Exception` 把崩溃、导入错误或连接错误包装成目标红态，会让坏探针看似“抓住了问题”，不算有效证据。

## 判定顺序

1. **前置有效性**：服务、权限、数据、夹具和依赖满足合同；否则记录环境/夹具问题，不伪造产品失败。
2. **反事实**：在隔离副本把目标错误恢复（例如去掉过滤、跳过审核、强制成功），目标探针必须因业务断言失败。
3. **修复后同输入**：相同入口、输入、数据和独立 oracle 复跑；变更了产品源码或构建就重新冻结摘要。
4. **状态对账**：检查用户响应、持久化、索引/文件、工具副作用、日志/事件和外部账本（适用时）。
5. **独立复核**：fresh-context 只读 verifier 只读冻结候选和原始证据；它不改实现、不重写 expected、不自我批准。

## 结果分类

- 断言在有效环境下观察到真实违约：`FAIL`。
- 需要的边界、oracle、原始结果或反事实不可用：`INCOMPLETE`。
- 服务/凭据/依赖未满足而无法执行：`BLOCKED` 或 `NOT_RUN`。
- 检查器只验证结构，未能证明行为：能力保持未交付/切片状态，不得写 `PASS`。

## 正例也要独立

负例变红不代表正例正确。至少准备一个由人工或业务系统确认的有效输入，验证修正版确实接受它；这个正例的 expected 不得由被测输出、同一 prompt、同一模板或同一常量计算。对于文本答案，格式正则可以作为附加约束；事实关系、否定、单位、权限和后置动作必须另有真值。
