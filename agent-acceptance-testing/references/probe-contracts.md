# 探针契约：独立、可失败、可复查

本参考适用于任何 Agent 检查器。它定义怎样证明一条探针在测行为；不绑定字段名、协议、模型、框架、业务域或部署形态。架构相关的示例见 [架构模式库](architecture-patterns.md)，只在适用性画像选择后读取。

## 最小契约

每条探针必须声明：

1. **入口和边界**：真实用户入口、公开 API、CLI、批处理、事件消费者或受控内部接口；测试替身替代了哪一层。
2. **前置状态**：身份、权限、数据、配置、依赖、时间、外部对象和夹具是否有效。
3. **外部输入**：输入由测试资料、人工真值或外部系统提供，不能从生产代码、prompt 或现成答案复制。
4. **允许行为**：可接受输出/动作集合、禁止输出/动作、状态转移和副作用上限。
5. **独立 oracle**：人工确认事实、公开合同、协议 schema、状态不变量、权限矩阵或外部只读记录；不能由被测输出计算。
6. **后置核对**：用户结果、持久化、权威记录、文件/索引、事件、工具副作用和清理结果（仅核对适用项）。
7. **失败语义**：有效环境下的产品违约、无效夹具/环境、缺证据和未执行分别如何归类。

## 防止“有形状、没行为”的检查

下列信号只能作为辅助，单独出现时不得通过：

- HTTP 或命令成功码；
- 字段存在、字符串非空、计数大于零或状态文本匹配；
- 模型/执行器自报“已调用”“已完成”；
- 两个缺失值相等、空 ID 相等、同一固定答案重复出现；
- 页面健康或成功提示；
- 只验证日志/trace 中出现了节点名、工具名或步骤名。

先保存原始输入/响应和退出码，再检查类型、非空、范围、身份/范围、版本、来源锚点、输入影响、真实副作用和后置读回。期望值不得从这次实际答案复制、转义、快照化或拼接正则；正则只约束格式，不能证明事实关系、语义、权限或动作结果。

## 反事实和变异

对关键契约至少选择一个单根因反例：固定输出、忽略输入、一律拒绝/成功、跳过授权或审核、移除范围过滤、吞掉异常、让配置不生效、把失败替换成默认值。变异只在隔离副本运行，目标探针必须因业务断言失败；收集为空、依赖缺失、连接失败或进程崩溃不算捕获成功。

如果修复先于红态，使用父版本、定向回退或等价变异恢复反事实；恢复不了时保留“修复后通过但回归证明不完整”。历史结果和红态原件不得覆盖。

## 异常边界和证据封存

探针只捕获可命名、预期的解析或业务异常；未预期异常保留原始堆栈并以非零退出或明确 `INCOMPLETE` 结束。不要用宽泛捕获把崩溃、导入错误、网络错误或错误夹具包装成目标红态。

所有并行生产者和审查句柄停止写入后才计算证据 digest。摘要后新增文件、修改原始记录或补写状态，都必须把旧摘要标记为 `SUPERSEDED` 并重新冻结；不得用后来的绿态覆盖先前红态。

## 结果分类

- **`FAIL`**：前置和 oracle 有效，真实入口出现可复现的产品违约。
- **`INCOMPLETE`**：缺少独立 oracle、必要后置读回、反事实、required layer 或只完成命名切片。
- **`BLOCKED` / `NOT_RUN`**：服务、凭据、依赖、授权或资源不可用，尚未执行。
- **测试缺陷**：输入/夹具本身无效；修复夹具后重新执行，不能把它当产品能力通过。

负例变红不代表正例正确。至少用一个由人工或业务系统确认的有效输入验证修正版；正例 expected 不得由被测输出、同一模板、同一常量或同一裁判生成。
