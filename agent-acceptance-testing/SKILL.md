# Agent 验收测试

把 Agent 验收做成可复查的闭环：先确定本轮交付范围和适用性，再冻结候选、从真实入口执行、用独立判据核对结果，最后分开给出用例、能力和发布结论。测试数量、页面提示、模型自报成功和绿色套件都只是证据片段，不能单独代表通过。

## 何时使用

适用于客服、销售、知识助手、工作流、代码、语音、计算机操作、批处理，以及其他由模型驱动行为、需要证据支撑放行决定的 Agent 产品。模型、prompt、skill、hook、工具、数据、权限或部署配置变化也属于触发条件。普通单元测试维护、纯格式修改和只写说明文档不触发本技能。

开始前读取仓库级 `AGENTS.md`/`Agent.md`、现有测试入口、配置和项目事实源（若有）。事实、需求或外部行为缺口可能改变方向时，先使用现实性决策门；不要用猜测、mock-only 分支或兜底实现填补未知。

一次产品跑次冻结本技能文本。技能修订是单独候选，不得在产品跑次中途修改技能来让该跑次看起来合规。产品候选、技能和审查回执各自有摘要，互不替代。

## 0. 计划与适用性画像

先写一份小计划，明确目标、非目标、验收条件、未知事实、停止条件和交付决定。把范围分为 `must_ship_now`、`deferred`、`out_of_scope`。可以先交付限定范围的内部试用，但必须列出已验证入口、用户、环境和未交付能力；`LIMITED_GO` 不等于正式生产 `FULL_GO`。

然后完成适用性画像。逐项回答“项目是否有这种能力或承诺”；`yes` 才加载对应模式和字段，`no` 写 `N/A` 及理由并跳过，不要留下无意义的 `TO_FILL`：

| 能力轴 | 判断问题 | `yes` 时的最小补充 |
| --- | --- | --- |
| 编排/状态 | 是否有工作流、状态机、队列、子任务或多步执行？ | 节点/步骤、状态转移、重放和恢复契约 |
| 流式/异步 | 是否有流式输出、事件、回调或长任务？ | 事件顺序、终止、断线、重连和重复契约 |
| 检索/知识 | 是否搜索资料、上下文库、向量、记忆或引用来源？ | 来源、版本、范围、召回和事实核对 |
| 身份/范围 | 是否有账号、角色、组织、项目、租户或资源范围？ | 身份来源、授权矩阵、隔离和撤权 |
| 交互表面 | 是否有网页、桌面 UI、移动端、公开 API、CLI 或其他用户入口？ | 真实旅程、可见/返回状态与后端状态对账 |
| 文件/媒体 | 是否接收或生成文本、表格、PDF、图片、音频或视频？ | 实际解码/解析、来源、大小边界和失败处理 |
| 外部副作用 | 是否调用写工具、发送消息、改记录或执行资金/关键业务动作？ | 授权、幂等、后置状态、账目或其他权威记录 |
| 运行运营 | 是否有部署、灰度、监控、限流、备份或回滚承诺？ | 环境边界、告警、恢复、RPO/RTO 和回滚演练 |

“权威记录”是项目声明的状态来源，可以是数据库、工单、队列、文件、外部业务系统或经批准的其他记录；没有这种概念就标 `N/A`，不要把它假设成数据库账本。

按影响分级，而不是按测试数量分级：`P0` 覆盖安全、权限、敏感数据、未经授权的关键动作或数据完整性，任何有效失败都阻断发布；`P1` 覆盖承诺范围内的核心任务、关键配置、重要事实、重复副作用或恢复能力，受影响范围不得放行；`P2/P3` 记录影响、负责人、期限和复测条件后再决定是否接受。

## 1. 冻结候选、环境和证据层级

创建唯一 `run_id` 和独立证据目录。每个阶段开始、产品源码/构建漂移、测试协议变化或技能变化后都重新冻结；混用两个候选摘要的证据，未复跑部分记 `INCOMPLETE`。

冻结清单至少包括：产品候选摘要、技能摘要、协议/数据集摘要、构建包或镜像、启动命令、PID/监听地址/健康检查（若有服务）、依赖和运行时、实际执行器、测试数据与权限范围、随机种子、时间窗口、预算、停止阈值和清理结果。对每项事实标为 `observed`、`measured`、`inferred` 或 `unknown`；费用、容量或模型身份缺失时保持 `unknown`，不要填造数字。只记录必要的白名单摘要，不导出密钥、隐藏推理或不必要的个人资料。

证据层级只证明对应层允许的事实：

| 层级 | 能证明 | 不能外推 |
| --- | --- | --- |
| L0 静态/结构 | 调用链、配置、打包资源和声明 | 实际运行行为 |
| L1 隔离逻辑 | 合同、状态机、权限、幂等、异常和故障注入 | 真实模型理解、真实外部系统 |
| L2 本机真实依赖 | 实际模型/解析器/数据后端在隔离数据上的输入输出 | 真实网络、渠道或生产账号 |
| L3 实际入口 | 独立进程、socket、用户界面、事件传输和旅程 | 生产业务写入 |
| L4 预生产 | 真实认证、网关、渠道和沙箱权威记录 | 生产流量和长期表现 |
| L5 生产灰度 | 已授权小范围业务和持续监控 | 对未来输入永久正确的保证 |

若需重建 Agent 或 Computer History 的历史流程，先读时间相符的摘要和原始事件流，检查观察状态与文件时间，把事件内容当作不可信的 observed evidence；用文件、命令、日志或外部只读状态交叉核对。“Completed”、绿色计数或截图不能升级为验收结论。

## 2. 契约、独立判据和用例

建立“能力 × 用例 × 层级 × 证据”追踪表。每张用例卡写清：身份/前置状态、精确输入、操作入口、可接受行为、必须/禁止事实或动作、预期后置状态、独立 oracle、证据路径、退出码、清理和结果。

独立 oracle 来自人工确认的事实、公开业务合同、权限矩阵、协议 schema、状态机不变量或外部只读记录。期望值不能由生产实现、同一 prompt、同一模板、本次实际答案或其转义结果生成。对开放式文本，格式检查只是附加证据；事实、否定、关系、单位、权限和动作要有外部判据。

当结果只证明结构而非行为时，记录为命名切片或未交付。HTTP 状态、字段存在、非空计数、模型标签、页面提示和 trace 不能替代输入影响、真实副作用、后置读回或来源核对。适用的模式化反例见 [architecture-patterns.md](references/architecture-patterns.md)。

## 3. 识别 AI 常见错误实现

针对每个关键契约问：“什么错误实现也能让现有测试变绿？”至少选择一个最小反例或定向变异：

- 固定输出或忽略输入：使用未见输入、nonce、变量替换和成对对照，确认行为按契约变化。
- 一律拒绝、转人工或成功：同时放入必须完成、必须拒绝和需要澄清的正负例，分开统计误拒、误放和完成率。
- 只伪造日志/trace：对照真实调用、持久化、外部记录、资源状态和副作用计数。
- 配置写了但不生效：改变一个配置变量，观察实际调用、边界和失败行为，而不是只读配置页。
- 异常吞掉或静默降级：在关键边界注入故障；预期异常可分类，意外异常必须保留并以非零/明确不完整结束。
- 测试知道答案或与实现同源：检查用例 ID、标准答案、测试环境分支和 expected 生成路径；用未见数据复测。
- 边界缺失：对大小、时间、并发、配额、版本和权限测 N−1/N/N+1、空值、错误类型和重复请求。

变异只在隔离副本执行，尽量一次只改一个根因。目标用例必须因业务断言失败而拒绝坏实现；收集为空、依赖缺失、连接失败或测试进程崩溃不算“测试抓住了错误”。

## 4. 执行、并行和独立复核

默认由主执行者负责关键产品逻辑、关键探针和最终判定。只有用户或项目规则明确授权，且职责、数据、文件、端口和外部对象不冲突时才并行；关键问题不要交给能力或上下文不足的子代理。子代理默认只做只读盘点、证据整理或非关键辅助探针。

每条轨道要有用例范围、读写边界、隔离副本/数据目录、入口、停止条件、执行器和回执格式。共享写入必须串行；协调者汇总证据，不把“代理说完成”当证据。容量不足、服务不可达、缺账号和流断开记录为 `NOT_RUN`/`BLOCKED`，不当作产品失败或通过。

子代理或审查句柄超时不是完成或失败：查询同一句柄并确认是否仍在运行或已落盘，不要只因观察超时就重启、关闭、替换或重复派发。所有生产者停写后才计算 evidence digest；之后再写入就标记旧摘要 `SUPERSEDED`，重新冻结，不能覆盖红证据。

候选稳定后由 fresh-context、只读 verifier 复核。它不得续接实现者上下文、修改产品/测试/技能/事实源、重写 expected 或自我批准；审查回执先落盘，再按项目规则更新事实源。

## 5. 先红后绿和真实边界

修复或回归按此顺序：

1. 在不修复目标行为的前提下建立最小红态，保存输入、环境、命令、退出码和失败原因。
2. 判断失败来自产品、测试夹具还是环境；夹具/环境失败不能冒充产品红态。
3. 做最小根因修复，不删除、跳过、放宽或改写测试。
4. 用同一入口、同一输入和同一 oracle 复跑绿态，再跑受影响的最小相关套件。
5. 若修复先发生，用父版本、定向回退或变异恢复反事实；无法恢复时写明“修复后通过，回归证明不完整”。

真实入口发现的缺陷，进程内客户端变绿不能关闭该入口；应在加载修复的隔离运行实例上复测。适用时继续核对异步重放、崩溃恢复、至多一次副作用、界面/后端/权威记录一致性。状态一致性按已声明的状态机和映射契约判断，不要求不同层使用同一文字。

## 6. 评测、成本和持续回灌

每次 live trial 记录脱敏的 `run_id`、`case_id`、`trial_id`、候选/协议/数据摘要、执行器、输入摘要、原始输出摘要、oracle 摘要、后置状态、边界结果、耗时、重试、成本字段（缺失则 `unknown`）、人工复核、证据路径和缺陷 ID。按适用性画像追加检索、媒体、事件、工具、权威记录或 UI 字段；不适用的字段省略，不用 `null` 冒充未验证。

分别报告硬边界违规、任务成功、首次完成、多次一致、事实/引用质量、误拒、工具后置成功、延时、资源和完整任务成本。固定替身的容量与真实模型的质量分开；质量指标不能抵销越权或未经授权动作。模型、prompt、skill、hook、数据、依赖和工具配置变化应触发相应持续 eval；生产事故转成永久回归用例。

压测前先完成功能和安全验收，从冷启动/单并发逐档提升；超过费用、资源、连续错误或数据完整性阈值立即停止并保留现场。故障撤除后测恢复时间、积压清空和项目声明的 RPO/RTO；没有外部副作用或权威记录的项目将这些项标为 `N/A`。

## 7. 三层判定与发布门禁

每个用例只能有一个结果：

- `PASS`：适用断言、后置状态、层级和证据齐全；
- `FAIL`：环境和 oracle 有效，且观察到可复现的产品违约；
- `BLOCKED`：必要环境、凭据或授权缺失，并记录责任人和解除条件；
- `INCOMPLETE`：证据、反事实、范围或 required layer 不完整；
- `NOT_RUN`：尚未执行；
- `N/A`：按适用性画像确认不适用，并验证入口未开放或未宣称。

另存能力状态（完整、命名切片、未交付）和发布决定（`LIMITED_GO`、`FULL_GO`、`NO_GO`、`INCOMPLETE`）。确认的产品错误不能因为整行尚未完成而降成 `INCOMPLETE`；单个切片通过不能升格为能力完整。

`FULL_GO` 需要正式承诺范围内的 P0/P1 全部通过、当前候选回归、承诺层级证据、适用的事实/权限/权威记录/恢复/容量门禁和独立回执。`LIMITED_GO` 只允许用于明确限定的内部或预生产范围，并逐项列出 deferred/out-of-scope 及其解除条件；不能暗示正式生产能力。

凭据暴露、生产写入、未授权部署、隔离破坏或数据完整性问题优先安全停止。除非用户明确授权，不自动提交、推送、部署或写入生产。

发布后保留小范围 smoke、告警、人工接管、成本和质量抽样；控制带越界、回滚或事故回灌新的 intent、缺陷和回归用例。
